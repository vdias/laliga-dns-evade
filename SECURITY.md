# Security Policy

## Supported versions

Security fixes are applied to the latest published release.

## Automated security checks

The repository uses complementary automated controls:

- **GitHub CodeQL** for static code analysis.
- **RustSec `cargo-audit`** for published security advisories affecting Rust dependencies.
- **GitHub Dependency Review** for dependency changes introduced by pull requests.
- **Dependabot** for dependency update pull requests and vulnerability alerts.
- **GitHub Artifact Attestations** for release build provenance.

These automated controls reduce risk but do not constitute a formal independent security audit or certification.

## DNS response modification

`laliga-dns-evade` intentionally modifies selected DNS responses.

The proxy only rewrites an address when:

1. the address is present in the configured blocklist; and
2. the address belongs to a configured Cloudflare network.

Addresses outside the supported rewrite policy are left unchanged.

## DNSSEC

An upstream resolver may validate DNSSEC and return a response with the `AD` (Authenticated Data) flag set.

If `laliga-dns-evade` modifies that response, the modified packet is no longer the exact authenticated response produced by the upstream resolver.

The proxy therefore clears the `AD` flag whenever it rewrites an address.

The project does not disable upstream DNSSEC validation and does not claim that a rewritten answer remains DNSSEC-authenticated.

## Network exposure

The reference configuration binds the proxy to:

```text
127.0.0.1:5335
```

Keep the rewriting proxy on loopback unless there is a specific, reviewed reason to expose it.

Client-facing DNS should normally be provided by a dedicated frontend with appropriate access controls and TLS configuration.

Do not expose an unrestricted recursive or forwarding DNS service to the public Internet.

## Runtime account

Run the service under a dedicated unprivileged account.

Reference account:

```text
laliga-dns-evade
```

The account should not have an interactive shell or home directory.

## Runtime data

Recommended permissions:

```text
/var/lib/laliga-dns-evade
  root:laliga-dns-evade 0750

runtime data files
  root:laliga-dns-evade 0640
```

Runtime files influence DNS response rewriting and must therefore be treated as trusted configuration.

## Update sources

The reference deployment consumes public data from:

```text
https://hayahora.futbol/estado/blocked-any.txt
https://www.cloudflare.com/ips-v4
https://www.cloudflare.com/ips-v6
```

An updater should download to temporary files, validate content, reject malformed or unexpectedly empty data, and preserve the current known-good files on failure.

## Release provenance

Release archives are generated by GitHub Actions from semantic version tags.

Each release archive receives a GitHub artifact attestation.

Users can verify provenance with:

```bash
gh attestation verify \
  <release-archive.tar.gz> \
  --repo vdias/laliga-dns-evade
```

Checksums are published as `SHA256SUMS` in every GitHub Release.

## Reporting vulnerabilities

Use GitHub Private Vulnerability Reporting when enabled for the repository.

Do not disclose sensitive vulnerability details in a public issue.
